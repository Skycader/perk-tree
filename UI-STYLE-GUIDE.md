# UI/UX стиль «Древо» — портативное руководство для ИИ

Это самостоятельный референс визуального языка проекта «Древо» (Homo Deus
perk tree), написанный так, чтобы его можно было скопировать в **любой
другой проект** и попросить ИИ («сделай в этом стиле») без доступа к
исходному коду. Все значения — реальные, взятые из CSS проекта, а не
приблизительные.

Стиль одной фразой: **военный HUD / техническая спецификация** — тёмный,
острый, монохромный по форме и монохромный по цвету категорий, где цвет —
это данные, а не украшение.

---

## 1. Палитра

### 1.1 Фон (три оттенка «почти-чёрного», не один плоский)

| Роль | HEX | Где |
|---|---|---|
| Фон страницы (самый тёмный) | `#080910` | `body` |
| Фон карточек/окон/попапов | `#0d0e18` / `#0f1018` | tooltip, окна, попапы |
| Фон панелей/подложек (топбар, инпуты) | `#0a0b13` – `#0c0d18` | топбар-градиент |
| Тёмная подложка строк таблиц (тёмная зебра) | `#0f1019` / `#12141e` | таблицы, чётность строк |

Никогда не берётся один плоский `#000`/`#111` на всё — фон, панель и
карточка внутри панели должны на 1–3 оттенка отличаться друг от друга, иначе
пропадает ощущение слоёв.

### 1.2 Единственный тёплый акцент

`#e09040` (оранжевый) — и **только он** используется для «это активно /
важно / кликабельно»: заголовок бренда, обводка при hover, активные кнопки,
акцентная точка перед заголовками. Никаких дополнительных «декоративных»
цветов сверху этого.

### 1.3 Функциональная (не декоративная) палитра категорий

Если в проекте есть категории/разделы — у каждой свой фиксированный цвет,
всегда один и тот же, никогда не смешивается с соседними. Пример набора
(7 цветов, включая «чёрный», который **не** плоский серый, а тёмно-кровавый):

| Категория | Насыщенный (иконки/заголовки) | Приглушённый (для линий/фонов 15-18%) |
|---|---|---|
| orange | `#e09040` | `#c87830` |
| red | `#cc3838` | `#a02828` |
| blue | `#3e80d0` | `#2860a8` |
| green | `#28a860` | `#208850` |
| purple | `#7840c8` | `#6030a8` |
| yellow | `#b89030` | `#907820` |
| black | `#505050`/`#303030` | `#303030` (не `#000`/`#111`!) |

Правило: **насыщенный** вариант — для иконок/цифр/акцентов, которые должны
читаться как «идентичность». **Приглушённый** — для линий-коннекторов и
залитых фонов, чтобы они не спорили с текстом.

### 1.4 Текст

| Роль | HEX |
|---|---|
| Основной текст | `#c0bdb4` |
| Яркий/заголовочный текст (имена, значения) | `#dedad2` |
| Вторичный текст (описания) | `#7a8090` / `#9098ac` |
| Приглушённый (лейблы, мета) | `#585e72` |
| Совсем тусклый (версии, служебное) | `#454a60` |
| Ссылки/код-акцент | `#7ab0d0` (голубой, только для `<code>`) |

### 1.5 Границы

Тонкие 1px рамки, всегда приглушённый сине-серый: `#2a3050` (границы окон/
попапов), `#1e2235`/`#1c1f2e` (границы карточек/строк), почти невидимые в
покое, светлеют или окрашиваются в акцент при hover/active.

---

## 2. Форма (углы)

Система **бинарная**: либо острый прямоугольник, либо идеальный круг —
ничего среднего, никаких «мягких карточек».

- `border-radius: 1–4px` почти везде (карточки, окна, теги, кнопки).
- `border-radius: 50%` только для точек-индикаторов, бейджиков, дотов
  слайдера.
- **Никогда** `border-radius: 8px+` на прямоугольных элементах — это сразу
  превращает HUD в «обычный современный UI».

---

## 3. Типографика

- **Один шрифт везде**: моноширинный (`'JetBrains Mono', monospace`) — не
  только для чисел/кода, но и для обычного текста описаний. Это ключевая
  деталь стиля: моноширинный текст на прозе читается как техническая
  спецификация, а не как проза.
- Размеры **мелкие**: `0.5625rem`–`0.75rem` (9–12px) для большинства
  лейблов/тегов/описаний; `0.8125rem`–`1.125rem` только для 2–3 главных
  заголовков экрана.
- `letter-spacing: 0.05em`–`0.18em` на заголовках/лейблах/тегах — шире
  обычного, придаёт «печатный», официальный вид.
- `text-transform: uppercase` на категориальных лейблах и мелких служебных
  подписях (не на основном тексте).
- `font-weight: 600–700` на заголовках/акцентах, `400–500` на теле текста.

---

## 4. Границы + тени (глубина без skeuomorphism)

Стандартная формула тени на карточке/окне:

```css
box-shadow:
  0 2px 8px rgba(0, 0, 0, 0.4),           /* мягкая тёмная тень вниз */
  inset 0 1px 0 rgba(255, 255, 255, 0.03); /* едва заметный блик сверху изнутри */
```

Для более крупных/приподнятых элементов (тултипы, модалки, popup):

```css
box-shadow: 0 8px 40px rgba(0, 0, 0, 0.9);
```

При hover — тень **усиливается**, не появляется с нуля:

```css
box-shadow:
  0 4px 16px rgba(0, 0, 0, 0.5),
  inset 0 1px 0 rgba(255, 255, 255, 0.05);
```

Правило: тень всегда тёмная и глубокая (`rgba(0,0,0,0.3–0.9)`), инсет-блик —
почти невидимый белый (`0.03–0.05` alpha), никогда мягких «material design»
серых теней с большим размытием и низкой непрозрачностью.

---

## 5. Градиенты — только диагональные

Заголовки секций/чипов/окон получают **диагональный** (120° или 135°,
никогда vertical/horizontal) градиент от цвета категории к почти
прозрачному:

```css
background: linear-gradient(
  120deg,
  rgba(200, 120, 48, 0.18) 0%,
  rgba(200, 120, 48, 0.07) 100%
);
border-color: rgba(200, 120, 48, 0.5);
```

Диапазон непрозрачности всегда узкий: **7–18%**. Это не заливка, а лёгкая
подсветка — если градиент заметен как «цветной блок», он слишком яркий.

Фон самой карточки (не заголовка) — тоже диагональный, но между оттенками
фона, не цвета категории:

```css
background: linear-gradient(135deg, #13151f 0%, #111320 50%, #0f1019 100%);
```

---

## 6. Акцентные квадраты — язык идентичности

Вместо иконок/эмодзи — маленький цветной квадрат `10×10px`,
`border-radius: 1px`, цвет = цвет категории/сущности. Появляется:
- перед главным заголовком экрана;
- как «иконка» перка/пункта дерева;
- перед заголовками секций сайдбара.

Это самый узнаваемый элемент стиля — если нужно одним движением показать
«вот эта штука активна/принадлежит категории X», не тянется иконка, а
рисуется квадрат нужного цвета инлайново (`display:inline-block;width:10px;
height:10px;background:{hex};border-radius:1px;vertical-align:middle`).

При hover на такой квадрат — свечение через `box-shadow`, не смена цвета:

```css
box-shadow: 0 0 6px 3px {hex}aa, 0 0 14px 5px {hex}44;
```

---

## 7. Анимация / движение

- Переходы **быстрые**: `0.15s`–`0.25s`, `ease` (не `ease-in-out`, не
  bounce). Ничего не должно ощущаться «playful» или «bouncy».
- Соединительные линии (SVG) отрисовываются через `stroke-dasharray` /
  `stroke-dashoffset`, анимируются «дорисовкой» от начала к концу:

```css
@keyframes dashIn {
  to { stroke-dashoffset: 0; }
}
/* line: stroke-dasharray/-dashoffset = длина пути, style="animation: dashIn .3s ease forwards" */
```

- Цвет соединительных линий везде одинаковый: `#50556a`, `stroke-width: 1.5`,
  круглый якорь `r="3"` того же цвета.
- Никаких fade/slide-переходов у попапов — появляются/исчезают через
  `display:none ↔ flex`, максимум лёгкий `opacity` без transform.

## 8. Компоненты — рецепты

### 8.1 Тег/чип (например «альтернативное имя», категория)
```css
display: inline-flex; align-items: center; gap: 6px;
font-size: 0.625rem; color: #7a8090;
background: #0f1018; border: 1px solid #1e2235; border-radius: 3px;
padding: 2px 8px 2px 6px;
```
+ маленькая точка-индикатор перед текстом (`::before`, `4-5px`, `border-radius:50%`,
серый `#3a4560` по умолчанию, или цвет категории).

### 8.2 Кнопка
```css
height: 1.5rem; padding: 0 14px;
font-size: 0.625rem; font-weight: 600; letter-spacing: 0.12em; text-transform: uppercase;
border: 1px solid #2a3050; background: rgba(224,144,64,0.07); color: #e09040;
transition: all 0.15s;
/* hover: background rgba(224,144,64,0.16); border-color: #e09040; */
```
Кнопки всегда с **фиксированной высотой**, не padding-driven — иначе разные
шрифтовые метрики дают разную высоту у соседних кнопок.

### 8.3 Заголовок секции / карточки (диагональная подсветка)
```css
padding: 8px; border: 1px solid {colorAlpha(0.5)};
background: linear-gradient(120deg, {color,0.18} 0%, {color,0.07} 100%);
box-shadow: 0 2px 12px {color,0.12}, inset 0 1px 0 rgba(255,255,255,0.04);
font-weight: 600; letter-spacing: 0.05em;
color: {насыщенный вариант цвета};
```

### 8.4 Всплывающее окно/тултип
```css
background: #0d0e18; /* или #0f1018 */
border: 1px solid #2a3050;
box-shadow: 0 8px 40px rgba(0,0,0,0.9);
/* header: padding 0.5rem 0.75rem; border-bottom: 1px solid #1c1f2e; font-size: 0.8125rem; font-weight:600; */
```
Кнопка закрытия — просто `✕` текстом, не иконка, `color:#585e72`, hover →
`#c0bdb4`, без фона и рамки.

### 8.5 Таблица
```css
border-collapse: collapse;
th { background: #0e0f16; font-size: 0.5625rem; letter-spacing: 0.14em; text-transform: uppercase; color: #585e72; }
td { padding: 0.1875rem 0.5rem; border-bottom: 1px solid rgba(28,31,46,0.5); }
tr:nth-child(odd) td { background: #12141e; }
tr:nth-child(even) td { background: #0f1019; }
```
Полосатость (zebra) — обязательна, но контраст между полосами минимальный
(разница в 2-3 пункта яркости фона, не белый/серый).

### 8.6 Скроллбар
```css
::-webkit-scrollbar { width: 4px; height: 4px; }
::-webkit-scrollbar-track { background: transparent; }
::-webkit-scrollbar-thumb { background: #1e2235; border-radius: 2px; }
::-webkit-scrollbar-thumb:hover { background: #2e3448; }
```
Тонкий (4px), тёмный, без track-фона — почти незаметен, пока не нужен.

### 8.7 Прогресс/заполнение (таймер, аудио-прогресс)
Тонкая полоса (`2-3px` высотой), заливка цветом акцента/категории на
прозрачном/тёмном треке, ширина или `stroke-dashoffset` анимируются из JS.

## 9. Что НЕЛЬЗЯ (антипаттерны этого стиля)

- ❌ Большие скругления (`border-radius > 4px` на прямоугольниках).
- ❌ Пастельные/светлые фоны, любой белый как фон карточки.
- ❌ Несколько разных «ярких» акцентных цветов на UI-уровне (акцент один —
  оранжевый; остальные цвета зарезервированы под категории/данные).
- ❌ Sans-serif/системный шрифт для тела текста — только моноширинный.
- ❌ Вертикальные/горизонтальные градиенты — только диагональные, и только
  «в почти прозрачное», не между двумя насыщенными цветами.
- ❌ Мягкие цветные тени (`box-shadow` в цвете акцента с большим blur и
  низкой density) вместо тёмных — единственное исключение: hover-glow на
  маленьких квадратах/иконках (см. §6), это осознанный акцент, а не общий
  тени-паттерн.
- ❌ Плавные bounce/spring-анимации, длинные (>0.3s) transition.
- ❌ Эмодзи/иконки там, где можно поставить цветной квадрат — эмодзи ломают
  ощущение «данные, не украшение» (кроме уже устоявшихся смысловых, вроде
  📜 для заметок — это по контенту, не по хрому интерфейса).

## 10. Чек-лист для ИИ: «примени этот стиль к новому компоненту»

1. Фон компонента — один из: `#080910` (страница) / `#0d0e18`-`#0f1018`
   (карточка) / диагональный градиент между двумя такими оттенками.
2. Граница — `1px solid #2a3050` (или `#1e2235` для менее важного элемента).
3. Тень — тёмная снизу + едва заметный белый инсет сверху (см. §4). Никогда
   голая тень без инсета на «приподнятых» элементах.
4. Шрифт — `'JetBrains Mono', monospace`, размер из диапазона `0.5625–
   0.8125rem`, если это не главный заголовок экрана.
5. Если нужен акцент «это важно/активно» — оранжевый `#e09040`, больше
   ничего.
6. Если элемент относится к категории/типу данных — цвет строго из
   зафиксированной палитры категорий (§1.3), одинаковый везде, где эта
   категория встречается.
7. Углы — `1–4px` или `50%`, третьего не дано.
8. Если нужна «иконка» для идентичности — цветной квадрат `10×10px`
   `radius:1px`, не эмодзи/SVG-иконка.
9. Hover — либо усиление тени, либо смена цвета границы на акцент, либо
   glow через `box-shadow` на маленьком элементе. Transition `0.15–0.25s`.
10. Никакого fade/slide на popup — `display:none ↔ flex`.
